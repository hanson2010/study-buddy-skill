# 学科资料导入（ingest_subject_workflow）

本文件定义**学科资料**（课本、讲义、笔记、题源、标准答案、范文等）的完整导入流程，从原件归档一直到触发编译。

> [!IMPORTANT]
> **升学资料**（招生政策、简章、投档线、一分一段、就业年报）走 [ingest_admission_workflow.md](ingest_admission_workflow.md)，那是一份**平级的完整流程**，不是本文件的子章节。分流在 SKILL.md 完成——agent 识别出资料族后直接读对应的那一份，不必两份都读。
>
> 两族的存储规则（原件归档、日期口径、log、`input/` 清理）刻意在两份文件里**各写一遍**：这样每份都自足，读一份就能把事情做完。代价是重复，收益是不必为了导入一份讲义去翻两百行投档线规则。
>
> 其他子命令在对话中遇到用户上传资料时，一律转 `ingest` 处理后再返回。例如 `aim` 讨论目标时用户发来招生简章，由 [ingest_admission_workflow.md](ingest_admission_workflow.md) 完成存储与编译，`aim` 继续做决策——与 `eval` 遇到作文时转 `essay` 的做法一致。

---

## 一、适用场景

按**资料类型**：
- **学习资料**：课本照片、讲义、笔记、知识点讲解等（可能一次涉及多个学科）
- **题源**：空白试卷、作业册、练习册（无学生作答，见下方「与 `eval` 的边界」）
- **参考材料**：标准答案、范文、教学大纲等（不计入错题统计，详见「参考材料隔离」核心规则 6）

> 若识别为招生简章、投档线、一分一段表、就业年报等升学资料 → 转 [ingest_admission_workflow.md](ingest_admission_workflow.md)，不在本流程内处理。识别线索：院校名称与招生代码、专业组代码、投档线/最低位次、分数段与累计人数、批次线、选科要求、就业率/深造率。

按**输入方式**：
- **GUI 直接上传**：用户在对话中直接上传图片或输入文字
- **`input/` 目录批量导入**：用户预先将多份待处理资料放入 `<STUDYBUDDY_DATA_DIR>/input/` 目录，由 Agent 扫描后逐个导入，每份成功后从该目录移入 `raw/sources/`

### 与 `eval` 的边界

试卷、作业册这类材料既可能属于 `ingest` 也可能属于 `eval`，**判据是有没有学生的作答**：

| 材料形态 | 路由 | 处理 |
|---|---|---|
| 有学生作答或批改痕迹（写了答案、老师打了勾叉） | **`eval`** | 逐题批改 → 错题写入 `raw/notes/` → 编译进知识点档案 |
| 空白卷 / 空白题册（只有题目，无作答） | **`ingest`** | 整份存为**一条「题源」记录**，只登记到学科 `_index.md` 的「导入资料」表；用户指定其中某题时才转 `eval` |
| 附标准答案的答案册 | **`ingest`** + `reference_type: standard_answer` | 沿用参考材料规则（核心规则 6） |

> [!IMPORTANT]
> **空白题册不逐题归档**。`eval` 的「空白题目 → 题目解答流程」只适用于**单题或少量题**的即时求解；把一本 200 题的练习册喂进去，会生成 200 条错题记录，污染错因史与正确率统计——学生一道都还没做。
>
> 整册的正确处理是：存为一条题源记录、保留题号索引，等学生真正做了哪几题再走 `eval`。

## 二、处理流程

### 1. 输入识别与路由

**输入来源**：
- **GUI 直接上传**：用户在对话中直接上传图片或输入文字资料
- **`input/` 目录扫描**：Agent 扫描 `<STUDYBUDDY_DATA_DIR>/input/` 目录（扁平，无日期层），逐个处理其中的待导入文件（忽略隐藏文件与子目录）。触发方式：用户明确要求处理 `input/` 目录，或提及"导入 input 里的资料""处理一下待导入文件夹"等类似表达；不主动、定期轮询该目录

**输入类型识别**（两种来源均适用）：
- **图片输入**：资料照片（课本页面、讲义、笔记等）
- **文字输入**：资料内容为纯文字（用户直接输入，或 `input/` 目录中的文本类文件）
- **混合输入**：图片资料并附带文字说明

**内容类型识别**：
- **学习资料**：课本内容、讲义、笔记、知识点总结
- **题源**：空白试卷、作业册、练习册
- **参考材料**：标准答案、范文、教学大纲
- **多学科资料**：包含多个学科的综合资料

> 识别为**升学资料**（招生简章、投档线表、一分一段表、批次线、招生政策、就业质量年报、专业介绍）时，转 [ingest_admission_workflow.md](ingest_admission_workflow.md) 走那份流程，本文件后续步骤不适用。

**本流程的步骤**：

```
输入来源（GUI 上传 / input/ 目录扫描）
  → 2. 学科识别
  → 3. 原件存入 raw/sources/YYYY/MM/
  → 3.5 非文本转换（如需）
  → 4. 解析（含建档粒度三问）
  → 5. 归档进 raw/notes/
  → 6. 按 topics 触发推式编译
  → 7. 记入 log
  → 8. 清理 input/（仅当来源为 input/）
```

### 2. 学科识别与分类

**学科识别方法**：
- **内容分析**：根据资料中的关键词、术语、公式等识别学科
- **用户指定**：用户明确指定资料所属学科
- **上下文推断**：根据对话上下文推断学科

**多学科资料处理**：

> [!IMPORTANT]
> 一份跨学科资料**只保存一份记录**，不再按学科复制多份。记录的 frontmatter 用 `subject` 标注主学科、`topics` 列出全部涉及的知识点；编译流程会自动把它引用进各相关学科的知识点档案。
>
> 若一份资料的内容确实可以物理拆分（如前 10 页物理、后 10 页化学），则按章节拆成独立的子记录，各自标注自己的 `subject`；但**不得把同一段内容复制两份**。

**支持学科**：语文、数学、英语、物理、化学、生物、政治、历史、地理（九科，枚举见 SKILL.md 的「学科短码」一节）

**未支持学科处理**：遇到未支持学科的资料时，简单跳过即可，不进行处理；用户询问时，可告知不支持该学科。

### 3. 原始资料存储

按照核心规则 2，将原始资料存储到 `raw/sources/YYYY/MM/` 目录：

- **存储时机**：在文件接收后**立即存储**，且**只存储一次**，后续处理步骤直接引用已存储的文件，不再重新拷贝
- **存储位置**：`raw/sources/YYYY/MM/`
- **年月取值**：按核心规则 1 取**事件日期**（资料本身可识别的日期），无法识别时才用当前时间
- **文件命名**：使用原始文件名存储，冲突时添加数字后缀
- **去重检查**：拷贝前必须检查 `raw/sources/YYYY/MM/` 目录中是否已存在同名文件，若已存在则跳过拷贝，直接使用已存在的文件路径
- **路径引用**：在处理结果文件的 `source_path` 中引用正确的相对路径

**来源为 `input/` 目录时**：先**复制**到 `raw/sources/YYYY/MM/`（去重逻辑同上），`input/` 目录中的原始文件此时**暂不删除**——只有在第 8 步确认该文件已完整走完导入流程后才会被移除，避免中途失败导致资料丢失。

### 3.5 非文本内容转换（本 skill 不负责）

> [!NOTE]
> **本 skill 仅处理文本内容**。若用户上传的原始资料不是文本（如图片、PDF、Office 文档等），本 skill **不直接对其进行 OCR / 格式转换**。
>
> - 由 Agent 自行选择当前环境中**其他可用的 skill 或工具**完成转换（本 skill 不指定具体工具），将其变为文本后再交给本 skill 处理。
> - 转换得到的文本进入下方「4. 资料解析」流程，原始非文本文件仍按第 3 步存入 `raw/sources/YYYY/MM/`，并在结果文件中引用其路径。
> - 若环境中无可用转换工具，提示用户先以文本形式提供资料（或手动转录），再继续导入。

### 4. 学科资料解析与完整内容保存

**解析内容**：
- **完整内容提取**：提取资料的全部内容，保留原始结构和格式
- **目录结构**：生成资料的完整目录结构（章节、小节等）
- **知识点提取**：按下方**两步法**得出 `topics` 数组——这是资料被编译进知识点档案「考点要义」的唯一依据
- **关键信息**：提取重要概念、公式、定理、例题等

#### 知识点提取：先答"考查什么能力"，再从词表挑

> [!CAUTION]
> **`topics` 严禁从文档的标题、目录、章节结构派生。**
>
> 知识点是"这份资料**考查什么能力**"，不是"这份资料**叫什么**"。把 `##` 标题、回目名、章节号、题型分节标题（「一、填空题」「二、简答题」）抄进 `topics`，是本流程**最常见也最具破坏性**的错误——它会让编译层长出成百上千个 `ch26`、`exercises-ch27`、`compilation-01` 这类空壳档案，每个都写不出「考点要义」，且把真正的知识点淹没。
>
> 判断方法：**把这个候选名单独拿给一位没读过这份资料的本科老师，他能说出这是什么知识点吗？** 说不出就不合格。「导数应用」「文言虚词用法」能；「第二十六回 蜂腰桥设言传心事」「二 简答题」「exercises」不能。

**第一步：问能力，不问结构。**

读完资料后回答一个问题——**这份资料在训练学生的哪几项能力？**限 **3-5 个**（一章教材、一份讲义通常就这么多）。这一步的输出是若干句自然语言描述，不是标题列表。

> 例：《红楼梦》第 26-60 回练习 → "考查名著整本书阅读中的**人物形象分析**与**情节梳理**，附带**语言鉴赏**"。而**不是**"有【重点内容·提示】【阅读难点·解读】填空题简答题四个部分"。

**第二步：把能力描述映射到受控词表。**

拿第一步的每句描述去 [topic_vocabulary.md](../templates/topic_vocabulary.md) 对应学科查规范名：

1. 先查学科 `_index.md` 的**知识点索引**——已有同名则复用其 slug
2. 再查**受控词表**——命中则直接用表中的规范中文名与 slug
3. 都不中才允许新造，且**必须在回复中告知用户**"新建了一个不在词表中的知识点：XXX"

这两步把"抽取题"变回"选择题"——**抽取会顺手抄标题，选择不会**。

#### 建档粒度三问（写入前的最后一道闸）

> `ingest` **可以**新建知识点档案——导入新章节时，档案带着「考点要义」先建好，学生首次做错时错因史直接叠上去。但**能不能建**取决于粒度，不取决于来源。判据与 [topic_templates.md](../templates/topic_templates.md) 第一节第 3 小节、[compile_subject_workflow.md](compile_subject_workflow.md) 第三节步骤 2 完全一致。

**这一步是治本处**：不合格的细点在**写入 `topics` 之前**就并入上位点，而不是让编译事后拒绝——否则 `topics` 里会留下指向不存在档案的键，触发体检 1.2。

1. **不可过大**：命中该科 `_index.md`「高频主题」列表，或需拆成 ≥3 个可独立出题的子点才讲得清 → 是 `theme` 不是 `topic`，写入其下位点
2. **不可过小且无发展余地**：三条至少满足两条——可独立出一组题（≥3 题）／会在不同材料与题目中反复出现／「考点要义」能写出可复用的结论。若它只是某上位点的一个义项、一个步骤、一个特例 → **并入上位点**，不单独写进 `topics`
3. **不可重复**：走上方第二步的三级查找

**必失败的形态**（出现即说明第一步跳过了、直接抄了结构）：

| ❌ 形态 | 例 | 正确做法 |
|---|---|---|
| 章节号 / 回目名 | `ch26`、`第二十六回 蜂腰桥设言传心事` | 归入「《红楼梦》整本书阅读」等能力点 |
| 题型分节标题 | 「一、填空题」「二、简答题」 | 题型不是知识点，丢弃 |
| 文档小标题 | 「【阅读难点·解读】」「【重点内容·提示】」 | 同上，丢弃 |
| 资料名 + 编号 | `hongloumeng 26`、`exercises` | 资料标识写 `title` 字段，不写 `topics` |
| 按年份 / 份数切 | `北京高考阅读2013年`、`默写过关检测7` | 十三年真题考的是同几个能力点，合并到那几个 |
| 流水号 / 随机串 | `compilation-01`、`topic-38eb063a` | 这是"没想清楚该叫什么"的产物，退回第一步重做 |

> `topics_role: coverage` 的记录（题源、考纲）**不过三问**——它的 `topics` 只是覆盖标注，粒度随原资料（题号索引或考纲条目）即可，不建档也就无所谓过大过小。但**上表的禁止形态与第二步的词表查找仍然适用**：覆盖标注里也不该出现 `ch26`，否则日后 `eval` 回链对不上。

> [!WARNING]
> **两步法与三问同样作用于 `sections[].topics`**。顶层 `topics` 是全部 `sections[].topics` 的并集（见下方 Frontmatter 说明），只过滤顶层而不过滤子文件，被并集重新带回来的正是那些标题碎片。**每个 `sections[].topics` 写入时都要走同一套流程。**

典型效果：一章「导数及其应用」不该提出 20 个名词各建一档，而应收敛成「导数概念」「导数的几何意义」「导数应用」等 3-5 个能持续积累的知识点，章内的「极值点判别」「单调区间求法」等作为要点写进这些档案的「考点要义」，不单独建档。

#### 按资料类型决定切分单元

**不是所有资料都按章节拆**。切分单元由资料类型决定：

| 资料类型（`ingest_type`） | 切分单元 | 编译去向 | `topics` 的作用 |
|---|---|---|---|
| `textbook` 课本 / `handout` 讲义 | 章 / 节 | 「考点要义」 | **编译连接键**（过三问） |
| `notes` 课堂笔记 | 主题段 | 「考点要义」 | **编译连接键**（过三问） |
| `reference_material` 标准答案 / 范文 | 按题 / 按篇 | 「考点要义」+「已用资源」 | **编译连接键**（过三问） |
| `classical_text` 古诗文篇目 | **篇** | 篇目档案（`topic_kind: memory_item`） | **编译连接键** |
| `memory_list` 必背清单 / 单词表 | **组**（20–50 条一组，**不是单条**） | 记忆项档案（`topic_kind: memory_item`） | **编译连接键** |
| `answer_pattern` 答题模板 / 得分点清单 | 题型 | 答题规范档案（`topic_kind: answer_pattern`） | **编译连接键** |
| `formula_sheet` 公式表 / 方程式汇总 | 整份或按模块 | 「考点要义」 | **编译连接键**（多数条目是义项级、过不了三问，归并到上位点后再写入） |
| `question_bank` 整份试卷 / 作业册（**空白**） | **不切**——整份一条记录 + 题号索引 | 只登记「导入资料」表 | **仅覆盖标注**，见下方说明 |
| `syllabus` 考纲 / 考试说明 | 整份 | 对学科 `_index.md` 的「高频考点」提出增删建议，**交用户确认后**才改；不自动改写静态章节 | **仅覆盖标注**，见下方说明 |

> [!IMPORTANT]
> **`topics` 有两种身份，不要混淆**：
>
> - **编译连接键**（上表前七类）：每一项都要过建档粒度三问，编译据此定位或新建知识点档案。缺失会被静默漏掉（核心规则 4）。
> - **仅覆盖标注**（`question_bank` / `syllabus`）：这两类资料**本身不承载知识内容**——一份空白卷是题目，一份考纲是目录。它们的 `topics` 只用于「导入资料」表的「覆盖知识点」列、日后 `eval` 回链、以及考点命中统计，**不触发建档、不并入任何档案正文**。
>
> 这不是按来源开后门——判据仍是内容性质：**有可沉淀的知识内容才做连接键**。题目和目录都没有。
>
> 这两类记录需在 frontmatter 标 `topics_role: coverage`，体检 1.2（未被任何档案引用的记录）对它们不适用。

> 本表只管**学科资料**。升学资料的切分依据是 `scope`（`entity` 枚举实体 / `bulk` 完整保留表格），见 [ingest_admission_workflow.md](ingest_admission_workflow.md) 第三节，不适用本表的「章/节/篇」口径。

**章节拆分的下限**：全书少于 3 章、或单章少于约 500 字时**不拆**，全部写进主文件——否则一份小讲义会在扁平的月目录下炸出十几个碎文件。

**结构化输出**：
- **扁平化存储**：所有记录在 `raw/notes/YYYY/MM/` 目录下扁平化存储，不建立 `<资料名称>` 子目录
- **主文件**：创建主文件 `<YYYY-MM-DD>-<subject>-<descriptive-slug>.md`，包含资料概述、目录结构和章节引用
- **子文件**：需要拆分时，按上表的切分单元保存为独立子文件 `<YYYY-MM-DD>-<subject>-<descriptive-slug>-<sub-slug>.md`，由主文件引用
- **子文件保存完整原文，主文件只保留目录与知识点索引**——「完整内容提取」指的是原文进子文件，**不是**把摘要写进主文件。资料的完整上下文是源层的核心价值，摘要化会让它永久丢失
- **每个子文件都要有自己的 `topics`**：这样某一章的内容才能被精确编译进对应知识点的档案，而不是整份资料笼统关联

**整份试卷/作业册（题源）的记录结构**：不拆子文件，主文件保留完整题目原文 + 一张题号索引表（题号 / 题型 / 涉及知识点 / 难度）。学生日后做了其中某几题，由 `eval` 处理那几题并在错题记录中回链本条题源记录。

#### 题源的权威分级与词表反馈

`ingest_type: question_bank` 的记录须标 `exam_authority`，它决定这份卷子能不能作为"考点分布"的证据：

| `exam_authority` | 含义 | 可否据此对受控词表提建议 |
|---|---|---|
| `gaokao_real` | 高考真题（含本省及全国卷） | ✅ 逐题比对，表外考点在回复中列出并建议补入 |
| `provincial_mock` | 省市统考／联考 | ✅ 但只提示，不催促——命题风格未必等同高考 |
| `school_mock` | 校内模考／周测 | ❌ 校内命题会把教师个人偏好当成高考趋势 |
| `unknown` | 来源不明 | ❌ 先请用户确认来源 |

配套字段：`exam_year`（年份）与 `exam_province`（适用省份）——全国卷、新高考卷、自主命题卷的考点分布不同，跨省混用会误导。

**agent 该做什么**：导入 `gaokao_real` 后，把逐题识别出的考点与 [topic_vocabulary.md](../templates/topic_vocabulary.md) 比对，**在本次回复中**列出表外考点并建议补入词表。

> [!WARNING]
> **只提建议，不自动改写**——词表随技能分发，改它属于技能维护；学科 `_index.md` 的「高频考点」是静态章节，同样不自动改（见 [index_templates.md](../templates/index_templates.md) 第 4 节）。
>
> **不做押题**：统计"近三年真题里这个考点考了 3 次"是事实；推断"今年会考"是虚假精确，与「不做录取概率预测」同源。少于 3 份 `gaokao_real` 时只报次数，不给高频／低频判定。

### 5. 学科资料归档与命名

**归档位置**：
- `raw/notes/YYYY/MM/<YYYY-MM-DD>-<subject>-<descriptive-slug>.md` — 资料主文件
- `raw/notes/YYYY/MM/<YYYY-MM-DD>-<subject>-<descriptive-slug>-<sub-slug>.md` — 各章节内容子文件

其中 `<subject>` 为学科短码（`chinese`/`math`/`english`/`physics`/`chemistry`/`biology`/`politics`/`history`/`geography`，跨学科用 `general`），定义见 SKILL.md 的「学科短码」一节。

**Frontmatter 模板**（主文件）：
```yaml
---
date: YYYY-MM-DD              # 事件日期，决定目录与文件名
ingested_at: YYYY-MM-DD       # 导入日期，仅作审计，不参与路径
subject: [学科]                # 九科之一；跨学科文档改用 doc_type
topics:                        # 必填数组，即使只有一个知识点
  - [知识点1]
  - [知识点2]
title: [资料名称]
ingest_type: textbook          # 取值与切分单元见第 4 步的资料类型表：
                               # textbook/handout/notes/question_bank/reference_material/
                               # classical_text/memory_list/answer_pattern/syllabus/formula_sheet
topics_role: compile_key       # compile_key（默认，topics 是编译连接键）
                               # coverage（仅覆盖标注，不建档不并入正文；question_bank 与 syllabus 用）
# 以下三项仅 ingest_type: question_bank 需要
exam_authority:                # gaokao_real / provincial_mock / school_mock / unknown
exam_year:                     # 卷子的年份
exam_province:                 # 卷子适用省份（全国卷填「全国甲」「新课标I」等）
source_path: raw/sources/YYYY/MM/<原始文件名>
reference_type:                # 参考材料时填 standard_answer/model_essay/classmate_essay，否则留空
total_pages: [总页数]
sections:
  - title: [章节标题1]
    file: [子文件名1]
    topics:
      - [知识点1]
      - [知识点2]
  - title: [章节标题2]
    file: [子文件名2]
    topics:
      - [知识点3]
---
```

> [!WARNING]
> 顶层 `topics` 是**编译连接键**（核心规则 4），必须是数组且必须存在。缺失时该资料会被编译静默跳过，学生在 learn 时读不到「考点要义」，且这类缺陷肉眼极难发现——数据体检会专门检查它。
> 顶层 `topics` 应为全部 `sections[].topics` 的并集。

**主文件内容结构**：
```markdown
# [资料名称]

## 资料概述
[资料的简要介绍和背景信息]

## 目录
- [章节标题1](<YYYY-MM-DD>-<subject>-<descriptive-slug>-<sub-slug>.md)
- [章节标题2](<YYYY-MM-DD>-<subject>-<descriptive-slug>-<sub-slug>.md)

## 知识点索引
| 知识点 | 对应章节 |
|--------|----------|
| [知识点1] | [章节标题1] |
| [知识点2] | [章节标题1] |
```

**扁平化存储的好处**：
- **目录结构简洁**：所有记录在 `raw/notes/YYYY/MM/` 下扁平化存储，不需要建立嵌套子目录
- **方便检索**：通过文件名模式匹配快速定位资料，便于按日期、学科检索
- **避免重复处理**：一次性保存完整内容，后续任务可直接提取相关章节
- **知识完整性**：保留资料的完整上下文，便于理解和学习

### 6. 触发增量编译（学科资料）

写入 `raw/notes/` 后，**立即**对该记录（含各子文件）`topics` 中的每个知识点执行增量编译，规则见 [compile_subject_workflow.md](compile_subject_workflow.md)。

> `topics_role: coverage` 的记录（题源、考纲）**跳过本步**——它们不建档、不并入任何档案正文，只登记到「导入资料」表。

- **档案不存在则创建**：新知识点生成档案骨架，`status` 为 **📘 已学未测**（`error_count = 0`，`evidence_strength` 留空）。`topics` 在第 4 步已过粒度三问，此处只做复用查找与建档
- **新建时回填历史资料**：档案是新建的，检索 `raw/notes/` 中命中同一知识点、且**日期早于本条**的既有记录，一并并入「考点要义」（见 compile_subject_workflow.md 增量编译第 3 步；重编时跳过）
- **写入「考点要义」**：把本资料中该知识点的核心结论并入档案的「考点要义」章节，并附来源链接
- **不触碰错因史**：资料导入不产生作答记录，因此**不进入**「个人错因史」，也不产生 `error_count` 与 `evidence_strength`
- **回填学科索引**：更新学科 `_index.md` 的「知识点索引」（新建档案在对应 `theme` 下新增一行，状态 📘）与「导入资料」表（新增一行记录日期、名称、类型、`raw/notes/` 路径、覆盖知识点）。**不写「薄弱点索引」**——资料导入不产生错误，📘 不是薄弱点

**参考材料的特殊处理**：`reference_type` 非空时，仍然编译进「考点要义」与「已用资源」（核心规则 6 的允许侧），但不计入任何统计。

**记录内容**：

- **编译更新**：刷新的知识点档案（标明哪些是**新建**、哪些是并入已有档案）

- **核心数据**：导入的资料数量、涉及的学科列表、总章节数、**过三问后的知识点数与归并掉的数量**、新建档案数

### 8. 移动 `input/` 中的原文件（仅当来源为 `input/` 时）

**触发条件**：仅当本次导入的原始资料来自「1. 输入识别与路由」中的 `input/` 目录扫描时执行本步骤；GUI 直接上传的资料不涉及本步骤。

**执行时机**：作为单份资料导入流程的最后一步，在第 4-7 步（解析、归档、编译、日志记录）**全部成功完成后**才执行——确保资料已可靠落盘，避免中途失败导致原始文件丢失且无处可寻。

**执行内容**：
- 该文件已在第 3 步复制归档至 `raw/sources/YYYY/MM/`，此时**移除 `input/` 中的副本**（等效于「移动」语义：原件保留在 `raw/sources/`，暂存区清空）
- 批量场景下逐个文件独立判断：仅移除**已完整走完第 4-7 步**的文件；未走完的一律**保留**在 `input/` 中不动——无论原因是解析失败、非文本转换不可用，还是学科不在九科枚举内——并在回复中逐个告知用户哪些文件未处理及原因
- 一批文件里若混有升学资料，那几份交由 [ingest_admission_workflow.md](ingest_admission_workflow.md) 处理，各自按那份流程的完成条件判断是否清理
- 移除失败（如权限问题）不阻断本次导入的其余部分，告知用户需手动清理该文件

> [!NOTE]
> 与旧版本的区别：旧版本直接**删除** `input/` 中的文件。现在原件一定先落在 `raw/sources/YYYY/MM/` 且保留原始文件名，因此 `input/` 只是纯粹的暂存区，清空是安全的，同时 `raw/sources/` 提供了完整的审计线索。

## 三、资料检索与复用

### 检索方式

遵循核心规则 8 的固定顺序，**优先读编译层**：

1. **知识点档案**（`subjects/<学科>/topics/<slug>.md`）的「考点要义」——绝大多数场景到这一层就够了
2. **学科 `_index.md`** 的「导入资料」表——需要知道某份资料整体结构时
3. **`raw/notes/` 主文件**——需要完整目录结构或章节导航时
4. **`raw/notes/` 章节子文件**——需要某章完整原文时
5. **`raw/sources/`**——需要看原始图片或文档时

> 升学资料的检索链路见 [ingest_admission_workflow.md](ingest_admission_workflow.md) 第六节，与本链路平级。

### 与 learn 的集成

- learn 时**先读知识点档案的「考点要义」**，而不是直接翻资料；档案里已经收敛了该知识点在各份资料中的核心结论
- 「考点要义」信息不足时，顺着档案 `sources` 数组定位到具体的 `raw/notes/` 章节子文件
- 仍不足时，再通过该记录的 `source_path` 找到 `raw/sources/` 中的原件

### 完整资料文件结构示例

```
raw/notes/2026/07/
├── 2026-07-14-math-algebra-functions.md                       # 资料主文件（目录结构和章节引用）
├── 2026-07-14-math-algebra-functions-01-introduction.md        # 第一章：引言
├── 2026-07-14-math-algebra-functions-02-derivative-concept.md  # 第二章：导数概念
├── 2026-07-14-math-algebra-functions-03-derivative-applications.md  # 第三章：导数应用
├── 2026-07-15-physics-formulas.md                              # 另一份资料主文件
└── 2026-07-15-physics-formulas-01-mechanics.md                 # 第一章：力学公式
```

编译后，第二章与第三章的内容分别进入：

```
subjects/数学/topics/derivative-concept.md
subjects/数学/topics/derivative-applications.md
```

**优势**：
- **一份内容一份存储**：跨学科资料不再复制多份，靠 `topics` 被多个档案引用
- **结构化检索**：通过档案快速拿到结论，通过主文件了解资料整体结构
- **精准定位**：按章节子文件直接提取相关内容，无需处理整个文件

## 四、使用示例

> 纯触发短语（导入课本资料、导入笔记、指定学科导入等）见第一节「适用场景」，此处只保留会触发非显而易见行为的示例。

### 输入示例0：导入整本空白练习册（题源）
```text
这是我们的数学暑假作业，还没开始做，先存一下。
[上传 PDF]
```
无学生作答 → 走本工作流而非 `eval`。整册存为**一条** `ingest_type: question_bank`、`topics_role: coverage` 的记录，主文件保留完整题目原文 + 题号索引表，**不拆子文件、不逐题归档、不建知识点档案**；`topics` 只作覆盖标注，登记进学科 `_index.md` 的「导入资料」表一行（题量 120、错题数 0、覆盖知识点若干）。学生日后做了第 12、15 题并拍照上传时，由 `eval` 批改那两题并回链本条记录、把「错题数」更新为 2——那两题的知识点这时才真正进入档案。

### 输入示例1：从 input/ 目录批量导入
```text
我把几份资料放到 input 目录了，帮我批量导入。
```
Agent 扫描 `<STUDYBUDDY_DATA_DIR>/input/`，逐个文件解析归档到 `raw/notes/`、触发编译，每份成功后从 `input/` 移除（原件已在 `raw/sources/`）；未能成功导入的文件保留在原地并在回复中说明原因。

### 输入示例2：一章课本的知识点归并
```text
帮我导入这一章"导数及其应用"。
[上传 PDF]
```
按第 4 步的**粒度三问**归并：章内出现的「导数定义」「导数的几何意义」「极值点判别」「单调区间求法」「最值问题」「零点与导数」等十余个名词，收敛为「导数概念」「导数的几何意义」「导数应用」3 个知识点写入 `topics`——其余作为要点写进这 3 个档案的「考点要义」，不各建一档。新建的档案状态为 📘 已学未测，回复中说明归并去向。

### 输入示例3：learn 对话中途上传资料
```text
（在讲解导数应用时）等下，这是老师发的补充讲义。
[上传图片]
```
`learn` 转本工作流完成存储、解析与编译，再回到 `learn` 继续讲解——用户无需切换命令。若上传的是升学资料（如投档线），则转 [ingest_admission_workflow.md](ingest_admission_workflow.md)，同样回到原流程。

> **升学资料的导入示例**（招生简章、投档线全量表、就业质量年报）见 [ingest_admission_workflow.md](ingest_admission_workflow.md) 第十节。
