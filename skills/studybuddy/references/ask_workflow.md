# 学情提问工作流（ask_workflow）

本文件定义 `ask` 子命令的处理流程：基于本地学习数据回答学生与家长的只读问题。

> [!IMPORTANT]
> **`ask` 是只读的**。它不创建、不修改、不删除任何学习数据文件（`profile.md`、`_index.md`、`raw/`、`subjects/` 一律不写），唯一的写入是在 `output/YYYY/MM/YYYY-MM-DD-log.md` 追加一行提问记录。

---

## 一、适用场景

`ask` 归口那些**只需读取、不产生新学习内容**的问题：

| 问题类型 | 示例 |
|----------|------|
| **学情概况** | "我数学最近怎么样？"、"这个月进步了吗？" |
| **薄弱点排序** | "我哪些知识点还没掌握？"、"最该先补哪个？" |
| **历史回顾** | "上次导数那道题当时是怎么讲的？"、"我这个知识点错过几次？" |
| **错因追问** | "我为什么老是错电磁感应？" |
| **资源回顾** | "之前推荐给我的物理视频是哪个？" |
| **目标差距** | "离目标分还差多少？"、"按现在的进度够得着吗？" |
| **选科可行性** | "我的选科能报临床医学吗？"、"这个专业组我够条件吗？" |
| **专业了解** | "计算机专业出来干什么？"、"这个专业深造率多少？" |
| **数据定位** | "我上个月的月报在哪？" |

### 不属于 ask 的场景

| 用户意图 | 应走 | 原因 |
|----------|------|------|
| "讲一下导数应用" | `learn` | 需要走六步法与交互确认，会产生学习记录 |
| "帮我出几道题" | `learn` | 会产生练习记录，属于写入型 |
| "批改这道题" | `eval` | 写入型 |
| "生成本周周报" | `report` | 会生成报告文件，属于写入型 |
| "帮我把目标改成 XX 大学" | `aim` | 会写 `profile.md` 并触发编译 |
| "这是投档线，帮我导入" | `ingest` | 属于导入流程 |
| "检查一下我的数据有没有问题" | `maintain` | 属于维护流程 |

> 判断标准很简单：**回答完之后需不需要在数据目录里留下新的学习内容**。需要就不是 `ask`。若用户在 `ask` 过程中转向"那你给我讲讲"，明确告知将转入 `learn` 流程，再继续。

## 二、检索深度与顺序

严格遵循核心规则 8 的固定顺序，**命中即停，不再向下深挖**：

```
1. Root _index.md              → 启用学科状态概览、历次考试成绩、全局复习优先级
2. 学科 _index.md              → 该科知识点索引（全量，按主题分组）、薄弱点索引、正确率趋势、高频考点
   colleges/_index.md          → 目标索引：选科校验、最低位次、当前差距
3. subjects/<学科>/topics/     → 知识点档案：错因史、已用资源、掌握状态与证据强度
   colleges/groups/、majors/   → 升学档案：选科要求、历年录取、就业与深造
4. raw/notes/YYYY/MM/          → 原始加工记录：具体题目、完整解析、投档线原表
5. raw/sources/YYYY/MM/        → 原始上传件：手写原稿、试卷照片、简章扫描件
```

第 2、3 层各有学科与升学两条并行分支，按问题所属领域选一条即可，不必两条都读。

### 各深度的适用问题

| 深度 | 停在哪层 | 典型问题 |
|------|----------|----------|
| **速览** | 第 1-2 层 | "我数学怎么样"、"哪科最弱"、"上次考试排名多少" |
| **标准** | 第 3 层 | "我哪些知识点没掌握"、"为什么老错这个"、"推荐过哪些视频" |
| **深挖** | 第 4-5 层 | "上次那道题的完整解法"、"我当时是怎么写的" |

**不要越级**。回答"我哪些知识点没掌握"时读到第 3 层就足够，不必打开 `raw/notes/` 下的几十个文件——这正是编译层存在的意义。反过来，回答"当时那道题怎么解的"必须下沉到第 4 层，档案里的题目摘要不足以支撑。

### 归档数据

默认**跳过** `archive/` 下的已归档学年。若在活跃数据中找不到答案，且问题明显指向更早的时间（如"我高一的时候物理怎么样"），告知用户相关数据已归档，并询问是否需要一并检索。

## 三、回答规则

### 1. 必须给出处

每个结论都要能追溯到具体文件或考试。这是 `ask` 与"凭印象作答"的根本区别。

**正确示例**：

> 你导数应用一共错过 3 次，其中 5/12 作业和 6/20 月考都是**概念不清**（极值点判别），7/12 那次才是计算失误。
> 也就是说主要问题在概念，不是算得不准。
> 来源：`subjects/数学/topics/derivative-applications.md`

**错误示例**：

> 你导数掌握得一般，建议多练习。

（没有出处、没有具体数据、没有可行动信息。）

### 2. 区分「数据说的」与「我推断的」

基于档案数据的陈述直接给出；超出数据的推断必须显式标注：

> 你最近三周数学正确率从 72% 升到 81%（来源：数学 `_index.md` 正确率趋势）。
> **推断**：主要拉动来自函数与导数（该主题从 2 个待巩固降到 0 个），但样本只有 18 题，趋势还不太稳。

### 3. 说明证据强度

回答"掌握了吗"这类问题时，必须带上证据强度，不能只说状态：

> 三角恒等变换现在是 🟡 疑似掌握——你连续三次做对了，但三次都是我出的练习题（`generated`），还没有在考试或作业里验证过。下次月考如果这块不丢分，才能算真正过关。

### 4. 数据不足时直说

不要为了给出答案而编造或过度外推：

> 化学目前只有 2 条记录（都在 6 月），样本太少，现在下"化学是薄弱科"的结论不可靠。要不要先上传一次化学作业或卷面分析？

### 5. 简洁

`ask` 的价值是快速回答。除非用户要求详细展开，否则控制在几句话内，配一张小表即可。不要输出完整报告——那是 `report` 的职责。

## 四、典型问题的处理路径

### 1. "我哪些知识点还没掌握？按优先级排"

> [!IMPORTANT]
> **「还没掌握」有两种，必须分开回答**，混在一起会直接误导学生：
> - **⚠️ 待巩固 / 🟡 疑似掌握**——做过、错过或证据不足，需要**复习**；
> - **📘 已学未测**——资料导入建了档，但学生**从没做过这个点的题**，需要的是**找题测一次**，不是复习。
>
> 把📘混进复习优先级会让学生把时间花在"补一个还不知道会不会的点"上；反过来，完全不提它，学生也不知道自己有一批没测过的盲区。

1. 读各主修学科 `_index.md` 的**薄弱点索引**（只含 `error_count ≥ 1`）；
2. 按 `错误次数 × 时间衰减 ÷ 证据强度权重` 降序合并排序（公式见 [compile_subject_workflow.md](compile_subject_workflow.md)）；
3. 输出前 5-8 条，每条给出：学科、知识点、状态、错误次数、最近错误日期、证据强度；
4. 对排在最前的 1-2 条，打开其档案补一句主要错因；
5. **末尾单列一句未测提示**：从各科**知识点索引**统计 📘 已学未测的数量，按学科给出（如"另外你有 12 个知识点是导入资料时建的档、还没做过题——数学 5 个、物理 4 个、化学 3 个，需要的话我可以出题测一轮"）。不展开逐条列出，不与上面的复习清单混排。

### 2. "我为什么老是错 X？"

1. 打开 `subjects/<学科>/topics/<x>.md`；
2. 读「个人错因史」表，统计各错因类型的分布；
3. 若某一类错因占多数，直接指出（"三次里两次都是概念不清"）；
4. 检查 `prerequisites`——若前置知识点也是 `⚠️ 待巩固`，指出真实病灶可能在上游；
5. 若档案「下一步」中有未验证的错因假设，说明这一点，并建议走 `learn` 做定向诊断。

### 3. "上次那道题怎么讲的？"

1. 从档案的 `sources` 数组定位相关 `raw/notes/` 记录；
2. 按日期筛出用户所指的那次（不确定时先列出候选日期与题目摘要，请用户确认）；
3. 打开该记录，引用当时的解析；
4. 如需看手写原稿，再从该记录的 `source_path` 定位 `raw/sources/` 中的原图。

### 4. "离目标分还差多少？"

1. 读 `colleges/_index.md` 的目标索引——它已经汇总了各目标的最低位次、当前位次与差距；
2. 需要单个目标的细节（历年趋势、包含专业、数据年份）时，打开 `colleges/groups/<slug>.md` 档案；
3. 需要各科分数差距时，读 `profile.md` 的目标分与 Root `_index.md` 的最近一次成绩；
4. 若 `output/` 下有较新的 `gap_analysis` 报告，直接引用，不重复计算；
5. **以位次为主指标**回答，分数为辅；同时标注数据年份（如"这是 2025 年的位次，今年可能变化"）；
6. **不做录取概率预测**——只呈现分数与位次差距这些事实，把判断留给学生和家长。

### 5. "我的选科能报 XX 专业吗？"

1. 读 `profile.md` 的选科组合与选科状态；
2. 读 `colleges/majors/<slug>.md` 的 `common_requirement`，或 `colleges/groups/` 中相关专业组的 `subject_requirement`；
3. 直接给出校验结论（✅ 满足 / ❌ 不满足 / ⚠️ 部分满足）并说明依据；
4. 判为 ❌ 时**必须明确说出该目标不可达**，不要含糊——选科在高一下之后基本不可逆，含糊表述会让学生错过调整窗口；
5. 涉及是否要改选科的建议，提醒结合学校生涯老师与家长共同决定。

### 6. "这个专业出来干什么？"

1. 读 `colleges/majors/<slug>.md` 的「学什么」与「就业与深造」；
2. **每条数据带出来源与年份**（如"2025 年就业质量年报"）；
3. 档案不存在或数据缺失时直说，并提示可以由 `ingest` 导入就业质量年报；
4. **不做价值判断**——不说"这个专业好/不好"，只呈现数据。

## 五、操作概要记入 log 文件

`ask` 只追加**一行**记录，不写完整的操作记录块：

```markdown
## 提问记录

### YYYY-MM-DD HH:MM:SS
- **提问**：我哪些知识点还没掌握？ | **检索深度**：学科索引 + 3 个知识点档案 | **来源**：subjects/数学/_index.md、subjects/物理/_index.md
```

> 提问记录的价值在于让 `report` 能看出学生反复关心哪些点——反复追问同一个知识点本身就是薄弱信号。
>
> 触发短语示例见第一节「适用场景」的问题类型表，此处不重复列举。
