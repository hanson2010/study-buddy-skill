# 作业批改工作流（eval_workflow）

本文件定义通用作业批改的处理流程，支持多种题型和场景。**作文批改走 `essay` 子命令**，不在本工作流内处理。

---

## 一、适用场景

- **作业批改**：用户上传作业照片进行批改
- **试卷批改**：用户上传试卷照片进行批改
- **题目解答**：用户上传空白题目（无作答），请求解答
- **错题订正**：用户请求订正已有的错题

> 作文批改走 `essay` 子命令（对应 [essay_workflow.md](essay_workflow.md)），不在本工作流内处理。

---

## 二、处理流程

### 1. 输入识别与路由

**输入类型识别**：
- **图片输入**：用户上传作业/试卷/作文照片
- **文字输入**：用户直接输入题目内容
- **混合输入**：用户上传图片并附带文字说明

**内容类型识别**：
- **作业/试卷**：包含选择题、填空题、解答题、计算题、证明题等多种题型，含用户作答
- **空白题目**：仅含题目描述，无用户作答
- **其他**：标准答案、范文等参考材料

**路由逻辑**：
```
用户输入
    │
    ├── 图片输入
    │       │
    │       ├── 识别为作业/试卷（含作答） → 执行通用批改流程
    │       │
    │       └── 识别为空白题目（无作答） → 执行题目解答流程
    │
    └── 文字输入
            │
            ├── 识别为作业/试卷（含作答） → 执行通用批改流程
            │
            └── 识别为空白题目（无作答） → 执行题目解答流程
```

> 题目解答流程：跳过「答案判断」和「错误分析」，直接生成解析；仍按归档原则进行错题归档。

> [!IMPORTANT]
> **「空白题目 → 题目解答流程」只适用于单题或少量题（约 10 题以内）的即时求解。**
>
> 整份空白卷、整本练习册、整册暑假作业**不走本工作流**，转 `ingest` 存为一条「题源」记录（见 [ingest_subject_workflow.md](ingest_subject_workflow.md) 的「与 `eval` 的边界」）。理由：整册逐题归档会生成上百条错题记录、污染错因史与正确率统计，而学生一道都还没做。等学生真正做了其中哪几题，再把那几题交给本工作流。
>
> 判据是**有没有学生的作答**：有作答或批改痕迹 → `eval`；只有题目 → `ingest`。

> 若识别为作文，提示用户使用 `essay` 子命令；不在本流程内处理。

**未支持学科处理**：本技能支持九科（语文、数学、英语、物理、化学、生物、政治、历史、地理）。识别作业/试卷所属学科后，若为未支持学科，简单跳过即可，不进行批改处理；用户询问时，可告知不支持该学科。

### 2. 图片处理（如适用）

当用户上传图片时，进行以下处理（图片存储与 OCR 识别由环境能力或其他 skill 负责，本工作流只接收已识别的内容）：

- **日期确定**：按核心规则 1 取**事件日期**（试卷/作业日期），无法识别时才用当前时间
- **图片存储**：保存到 `raw/sources/YYYY/MM/` 目录，存储时机为文件接收后立即存储，且只存储一次；拷贝前检查是否已存在同名文件，若已存在则跳过拷贝，直接使用已存在的文件路径
- **OCR 识别**：将图片内容转换为文字
- **内容结构化**：提取题目类型、知识点、答案等信息

### 3. 题目解析与批改

**题目类型识别**：
- **选择题**：识别题目描述、选项、用户答案
- **填空题**：识别题目描述、填空位置、用户答案
- **解答题**：识别题目描述、用户解答过程、最终答案
- **计算题**：识别已知条件、计算过程、最终答案（含单位）
- **证明题**：识别已知条件、求证结论、证明过程
- **判断题**：识别题目描述、用户判断

**批改流程**：
1. **题目理解**：分析题目要求和解题思路
2. **答案判断**：对比用户答案与正确答案（空白题目跳过此步）
3. **错误分析**：归类错误类型（概念不清、计算失误、审题错误、方法不当）（空白题目跳过此步）
4. **解析生成**：提供详细解答步骤和思路
5. **知识点标注**：标注涉及的知识点和难度等级

### 4. 错题归档

**归档原则**：默认进行归档。仅当用户上传材料完全正确时，跳过归档。

**归档条件**（满足任一即归档）：
- 题目答案错误
- 解答过程有错误（含步骤错误、方法不当、计算失误等）
- 题目未作答（空白题目请求解答）
- 用户主动要求归档

**归档流程**：
1. **文件生成**：创建 `raw/notes/YYYY/MM/<YYYY-MM-DD>-<subject>-<descriptive-slug>.md` 文件（`<subject>` 为学科短码，如 `math`）
2. **Frontmatter 填写**：包含学科、**全部命中的知识点**、难度、错误类型、来源类型等信息
3. **内容写入**：写入题目描述、用户答案、正确答案、解析、图片引用等
4. **回链题源（如适用）**：本次批改的题目若来自此前 `ingest` 导入的题源记录（整份试卷/作业册），在 frontmatter 的 `source_record` 中记录该题源记录的路径与题号，并回填学科 `_index.md` 「导入资料」表该行的「错题数」——这样"这套卷子做了多少、错了多少"无需在编译层另建整卷档案就能回答
5. **触发增量编译**：对 `topics` 中的每个知识点执行增量编译（见第 5 节第 6 步）

**Frontmatter 模板**：
```yaml
---
date: YYYY-MM-DD              # 事件日期（试卷/作业日期），决定目录与文件名
ingested_at: YYYY-MM-DD       # 导入日期，仅作审计，不参与路径
subject: [学科]
topics:                        # 必填数组：一道综合题命中的全部知识点
  - [知识点1]
  - [知识点2]
difficulty: medium             # easy/medium/hard
question_type: [题目类型]
error_type: [错误类型]          # 概念不清/计算失误/审题错误/方法不当
error_type_is_hypothesis: false # 同一知识点第 3 次出错时置 true，见第三节「错因假设验证」
source_type: homework          # exam（考试）/ homework（作业、原卷）/ generated（技能内生成的练习）
is_weak_area: false            # runtime-derived
source_path: raw/sources/YYYY/MM/<原始文件名>
source_record:                 # 题目来自此前导入的题源记录时填写，否则留空
  path: raw/notes/YYYY/MM/<YYYY-MM-DD>-<subject>-<slug>.md
  question_nos: [12, 15]       # 本次批改的题号
correct_rate: [正确率]
reference_type:                # 参考材料时填写，否则留空
videos:                         # 本次辅导（六步法第 3 步）推荐的视频，结构与 learn_workflow 一致
  - title: [视频标题]
    url: [视频链接]
    watched: [true/false]      # 学生是否确认看过，回填档案「已用资源」
---
```

> [!WARNING]
> `topics` 必须是**数组**（核心规则 4）。一道题同时考「导数应用 + 函数单调性」时两个都要列——只写一个会让另一个知识点的档案永远收不到这次错误。
>
> `source_type` 决定证据强度：技能内当场生成的练习一律标 `generated`，它**不足以**把知识点判定为「✅ 已掌握」。
>
> `videos` 未推荐视频时留空数组，不要省略这个字段——省略会让编译无法区分"没推荐"与"忘记记录"。

### 5. 智能辅导六步法（错题辅导与交互确认）

对错误题目执行「智能辅导六步法」，并进行交互式断点控制：

1. **诊断/识别**：图片识别并判定对错，确认涉及的知识点；打开对应知识点档案，命中历史薄弱点时高亮提示
2. **错因分析**：深入分析错误原因，归类错因（概念/计算/审题/方法等），并**与档案「个人错因史」中的历史错因比对**——同类要明确说出（如"这已经是第 2 次因为概念不清错在极值判别"）。同一知识点第 3 次出错时转入第 9 节的错因假设验证。
3. **视频推荐**：在分步讲解前，先推荐 1-2 个国内平台的概念/方法类微课视频或提供搜索关键词。推荐前先读档案「已用资源」，不重复推荐学生已看过且反馈无效的视频。**推荐结果写入本条记录 frontmatter 的 `videos` 数组**，供编译时回填档案「已用资源」（见 [compile_subject_workflow.md](compile_subject_workflow.md) 第四节第 3 点）。
4. **分步讲解**：分步进行解答，并使用图形、图表辅助讲解或进行原图标注。
   - **交互断点**：分步讲解完成后，**必须暂停并主动向用户确认是否理解、有无疑问**，严禁未经用户确认直接输出练习题目。
5. **举一反三**：在用户做好练习准备后，生成三层难度梯度的练习题，提供答案和易错提醒。此处的作答记录一律标 `source_type: generated`。
6. **归档/同步**：先把错题记录写入 `raw/notes/YYYY/MM/`，再对 `topics` 中每个知识点执行**增量编译**（见 [compile_subject_workflow.md](compile_subject_workflow.md)），刷新档案的错因史、状态、证据强度，并回填学科 `_index.md` 的知识点索引与薄弱点索引（本次出错的知识点 `error_count ≥ 1`，两张表都要更新；若该点此前是 📘 已学未测，状态就此转为 ⚠️ 待巩固）与正确率趋势。

### 6. 相似错题检测

**检测流程**：
1. **按知识点精确命中**：用本次识别出的 `topics`，直接查学科 `_index.md` 的**知识点索引**（全量表）是否已有同名知识点；命中则打开其档案。**查知识点索引而不是薄弱点索引**——后者只含出过错的，📘 已学未测的档案不在其中，用它去查会漏掉"导入过资料、这次第一次做错"的知识点，凭空多建一份档案
2. **读错因史**：从档案的「个人错因史」表读取历次记录，比对本次错因是否与历史同类
3. **复习提醒**：发现同知识点历史错题时提醒用户复习，并**明确指出错因是否重复**——「同一个知识点错了 3 次，其中 2 次都是概念不清」比「这个知识点错过 3 次」有用得多
4. **档案不足时下沉**：需要看当时的完整题目与解析时，顺着档案 `sources` 数组定位到具体的 `raw/notes/` 记录

> 与旧版本的区别：旧版本靠遍历日期目录做文件名模糊匹配，既慢又容易漏。现在靠 `topics` 字段精确命中知识点档案，一次读取即可。

### 7. 闪卡复习

**闪卡生成**：
- **正面**：题目描述和用户错误答案
- **背面**：正确答案、解析、知识点

**复习方式**：
- 间隔重复复习
- 根据薄弱点优先级排序

### 8. 操作概要记入 log 文件

每次执行作业批改流程后，必须将操作概要记入 `output/YYYY/MM/YYYY-MM-DD-log.md` 文件：

**记录内容**：
- **操作类型**：作业批改/试卷批改/题目解答/错题订正
- **处理的文件**：`raw/sources/` 中的原件路径、识别的题目内容
- **学习时长**：本次批改/订正耗时（分钟）
- **生成的文件**：创建的错题记录文件路径
- **编译更新**：刷新的知识点档案及其状态变化
- **更新的索引**：更新的 `_index.md` 文件及其内容摘要
- **核心数据**：批改题目数量、正确率、新增薄弱点数量

**记录格式**：
```markdown
## 操作记录

### YYYY-MM-DD HH:MM:SS
- **操作类型**：作业批改
- **处理文件**：raw/sources/2026/07/photo.jpg
- **学习时长**：30 分钟
- **生成文件**：raw/notes/2026/07/2026-07-12-math-derivative-applications.md
- **编译更新**：subjects/数学/topics/derivative-applications.md（错因史 +1，⚠️ 待巩固，证据 medium）、subjects/数学/topics/function-monotonicity.md（错因史 +1）
- **更新索引**：subjects/数学/_index.md（薄弱点索引 2 行，正确率趋势）
- **核心数据**：批改5题，正确率80%，新增1个薄弱点
```

## 三、错因假设验证

同一知识点**第 3 次**出错时，错因判定从「结论」降级为「假设」并加以验证。不验证的错因判断会一直错下去，导致学生反复补错地方。

### 触发与执行

1. **触发**：增量编译发现某知识点 `error_count` 达到 3，且档案「个人错因史」中某一类错因占多数。
2. **记录假设**：在档案「下一步」写入当前假设（如「假设：概念不清，而非计算能力」），并把本次记录的 `error_type_is_hypothesis` 置为 `true`。
3. **定向诊断**：下次辅导时生成 **2 道诊断题**，用于分离病灶：
   - **A 题**：只考概念判断，**计算量为零**（如"下列关于极值点的判断哪个正确"）
   - **B 题**：计算量大，但**概念条件直接给出**（如"已知 f'(x) 在 x₀ 两侧变号，求…"）
4. **判读**：

   | A 题 | B 题 | 结论 |
   |------|------|------|
   | ❌ | ✅ | 确认「概念不清」 |
   | ✅ | ❌ | 实为「计算失误」，修正档案中的错因判定 |
   | ❌ | ❌ | 前置知识点缺口，沿 `prerequisites` 向上追溯 |
   | ✅ | ✅ | 疑为「审题不细」或偶发失误，观察下次 |

5. **回写**：把结论与验证依据写入「个人错因史」的备注，清除该假设，`error_type_is_hypothesis` 复位。
