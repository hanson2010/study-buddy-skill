# 数据维护工作流（maintain_workflow）

本文件定义 `maintain` 子命令的处理流程，包含五项独立操作：**数据体检**、**档案清理**、**重新编译**、**全量重编**、**学年归档**。

> [!IMPORTANT]
> **本工作流不依赖任何随本 skill 分发的脚本**。全部检查由 Agent 按本文规则执行（与 SKILL.md 的「非文本内容的转换边界」一致）。若用户所在项目自带维护脚本，可以使用，但那是用户项目的工具，不是本 skill 的一部分。

---

## 一、适用场景

| 操作 | 触发表达 | 是否改写数据 |
|------|----------|--------------|
| **数据体检** | "给学习数据做个体检"、"检查一下数据有没有问题" | ❌ 只报告 |
| **档案清理** | "档案名字全是乱码，清理一下"、"合并重复的知识点档案" | ✅ 按模式**批量**删除/合并编译层档案（源层不动），见第二节之二 |
| **重新编译** | "把数学重新编译一下"、"这个知识点档案好像不对，重编一下"、"某专业组数据错了，重新编译" | ✅ 重建**单一学科**或**单一升学目标**（专业组/专业）的编译产物（源层不动） |
| **全量重编** | "把知识点档案全部重新编译"、"档案整体都不对，全部重建一下" | ✅ 重建**整个**编译层（源层不动） |
| **学年归档** | "把高一的数据归档"、"新学年了，整理一下旧数据" | ✅ 移动源层子树 |

未指明具体操作时，默认执行**数据体检**，并在结果末尾提示其余四项可用。

> **重新编译 vs 全量重编**：全量重编会删除并重建 `subjects/` 与 `colleges/` 下的**全部**档案，删除面大、重放成本高。若问题只集中在一个学科或一个升学目标（体检报告的 1.x 类问题不跨学科，或用户只提到某一科/某一专业组），优先用范围更小的**重新编译**；只有问题跨越多个学科/目标，或编译规则本身变更时，才需要全量重编。详见第三、四节。

---

## 二、数据体检

### 核心原则

> [!WARNING]
> **只报告，不自动修复**。体检输出「问题清单 + 建议修复方式」，任何改写都必须经用户逐项确认。学生数据是不可再生的——把体检做成自动修复，一次误判就会造成永久损失。

### 检查项

#### 1. 编译层与源层一致性（学科族）

> 升学族的对应检查在第 5 组（5.13–5.15），因为它的编译是目标驱动的，一致性口径不同。

| # | 检查 | 说明 | 严重度 |
|---|------|------|--------|
| 1.1 | 档案 `sources` 中的路径是否都存在 | 记录被重命名或删除后未同步 | 高 |
| 1.2 | `raw/notes/` 中是否存在未被任何档案引用的记录 | 说明该记录没被编译，通常因缺 `topics`。**`topics_role: coverage` 的记录（题源、考纲）除外**——它们本来就不建档，只登记到「导入资料」表 | 高 |
| 1.3 | 学科 `_index.md` **知识点索引**的每一行是否都有对应档案文件 | 索引指向不存在的档案 | 高 |
| 1.4 | 每个档案是否都在学科 `_index.md` 的**知识点索引**中有索引行 | 档案存在但检索不到。**必须查知识点索引而非薄弱点索引**——薄弱点索引只含 `error_count ≥ 1`，用它去查会对每个 📘 已学未测档案误报 | 中 |
| 1.5 | 档案 `status`/`evidence_strength` 与索引表中的值是否一致 | 增量编译中断导致 | 中 |
| 1.6 | 薄弱点索引的每一行是否 `error_count ≥ 1`，且都能在知识点索引中找到 | 两表不同步；📘 档案被误写进薄弱点索引 | 中 |

#### 2. 必填字段

| # | 检查 | 说明 | 严重度 |
|---|------|------|--------|
| 2.1 | `raw/notes/` 每条记录是否有 `subject`（或 `doc_type`） | 缺失则无法归科 | 高 |
| 2.2 | `raw/notes/` 每条记录是否有 `topics` 且为**数组** | **最难肉眼发现**：缺失会被编译静默跳过 | 高 |
| 2.3 | 是否存在遗留的单值 `topic:` 键 | 迁移遗漏 | 高 |
| 2.4 | 每条作答记录是否有 `source_type` | 缺失导致证据强度算错 | 中 |
| 2.5 | 是否有 `ingested_at` | 缺失只影响审计，不影响功能 | 低 |
| 2.6 | `doc_type: admission_data` 的记录是否有 `scope` | **无法判断取数方式**（枚举还是查表），整条记录对编译失效 | 高 |
| 2.9 | `ingest_type: question_bank` / `syllabus` 的记录是否标了 `topics_role: coverage` | 漏标会让题源里的知识点被误建成档案（多为孤儿档案），或触发 1.2 误报 | 中 |
| 2.10 | `ingest_type: question_bank` 的记录是否有 `exam_authority`、`exam_year`、`exam_province` | 缺 `exam_authority` 无法判断这份卷子能否作为考点分布证据；缺年份省份会导致跨省跨年混用 | 低 |
| 2.7 | 升学记录是否有 `credibility` | 缺失则无法执行就业数据分级（与 5.8 互补：5.8 查档案侧是否混入 `questionable`，本项查记录侧是否根本没标） | 中 |
| 2.8 | `scope: bulk` 记录是否有 `province` 与 `year` | 缺 `province` 无法与高考省份匹配，缺 `year` 无法做超期提示 | 中 |

> 2.1–2.5 针对学科记录，2.6–2.8 针对升学记录；两族的必填字段不同，不要用学科口径去查升学记录（它本来就没有 `subject`/`topics`）。

#### 3. 路径与日期口径

| # | 检查 | 说明 | 严重度 |
|---|------|------|--------|
| 3.1 | `source_path` 指向的 `raw/sources/` 文件是否存在 | 去重或改名后未同步 | 高 |
| 3.2 | 记录所在 `raw/notes/YYYY/MM/`、文件名日期前缀、`source_path` 的 `raw/sources/YYYY/MM/` 三者是否同月 | 核心规则 1 的日期口径 | 中 |
| 3.3 | `subjects/<学科>/` 下是否出现 `YYYY/MM/` 日期目录 | **违反源层/编译层分离**，通常是迁移遗漏或规则回潮 | 高 |
| 3.4 | `raw/notes/` 文件名是否包含正确的学科短码 | 同日撞名风险 | 低 |
| 3.5 | `input/` 中是否有滞留文件 | 导入中断 | 低 |

#### 4. 统计自洽

| # | 检查 | 说明 | 严重度 |
|---|------|------|--------|
| 4.1 | 学科 `_index.md` 的正确率能否由 `raw/notes/` 记录重算得出 | 手工改动或编译中断 | 中 |
| 4.2 | Root `_index.md` 的学科状态概览是否与各学科 `_index.md` 一致 | 汇总未刷新 | 中 |
| 4.3 | 有加工记录的日期是否都有对应的 `output/YYYY/MM/YYYY-MM-DD-log.md` | 核心规则 16 未执行 | 低 |
| 4.4 | 档案的 `status` 是否与错因史、证据强度自洽 | 如证据为 `low` 却标「✅ 已掌握」 | 中 |

#### 5. 升学域

| # | 检查 | 说明 | 严重度 |
|---|------|------|--------|
| 5.1 | **目标与选科冲突** | `profile.md` 的选科组合不满足某目标专业组的选科要求，该目标**不可达** | **高** |
| 5.2 | `profile.md` 的目标列表与 `colleges/_index.md` 目标索引是否一致 | 目标变更后编译未跑 | 高 |
| 5.3 | `colleges/` 下是否出现日期目录 | 违反源层/编译层分离，同 3.3 | 高 |
| 5.4 | `scope: entity` 记录是否至少有 `colleges`/`groups`/`majors` 之一 | 缺失则编译无法定位，静默漏掉 | 高 |
| 5.5 | 每个目标专业组是否有可用的投档数据 | 缺数据则差距分析无法进行 | 中 |
| 5.6 | 专业组档案的 `latest_data_year` 是否超过 1 年 | 录取数据过期，需提示重新导入 | 中 |
| 5.7 | 专业档案的 `employment_data_year` 是否超过 2 年 | 就业数据可能失真 | 低 |
| 5.8 | 是否存在 `credibility: questionable` 却被写入档案的就业数据 | 违反数据分级规则 | 中 |
| 5.9 | 目标梯度是否合理（冲/稳/保是否齐备、是否全部集中在同一位次段） | 结构性提示，不代填 | 低 |
| 5.10 | `profile.md` 的选科组合与 `subjects/` 下已建的学科目录是否匹配 | 改选科后未重算启用范围 | 中 |
| 5.11 | Root `_index.md` 的学科状态概览是否只含主修学科 | 学考科目混入主表 | 低 |
| 5.12 | `colleges/scores-distribution.md` 是否与 `raw/notes/` 中实际存在的 `data_type: scores_distribution` 记录一致 | 新记录未登记，或记录已被移除但索引未同步 | 中 |
| 5.13 | `colleges/groups/`、`colleges/majors/` 档案 `sources` 中的路径是否都存在 | 记录被重命名或删除后未同步（对应学科侧的 1.1） | 高 |
| 5.14 | 每个 `groups/`、`majors/` 档案是否都在 `colleges/_index.md` 有索引行 | 档案存在但检索不到（对应学科侧的 1.4）；5.2 只查 `profile.md` ↔ 索引，查不到这一侧 | 中 |
| 5.15 | 档案 `current_gap.student_rank` 能否由 Root `_index.md` 最近一次成绩 + `colleges/scores-distribution.md` 重算得出 | 成绩录入后未刷新差距，或一分一段表换年后未重算（对应学科侧的 4.1） | 中 |
| 5.16 | `raw/notes/` 中是否有 `doc_type: admission_data` 的记录被误移入 `archive/` | 违反「升学资料不参与学年归档」，会导致下次全量重编丢失该年份的投档与位次数据 | 高 |

> **5.1 为什么是高严重度**：选科在高一下学期后基本不可逆。目标专业组要求物理+化学而学生选了物理+地理，意味着这个目标永远够不着——这是本技能能提前捕获的、后果最严重且完全可预防的错误，必须在体检里第一时间报出来。

#### 6. 内容质量

| # | 检查 | 说明 | 严重度 |
|---|------|------|--------|
| 6.1 | 是否有档案的 `sources` 中含 `ingest` 类记录、「考点要义」却为空 | **回填没跑**（增量编译第 3 步）。若压根没有 `ingest` 来源，则只是提示可导入教材资料补齐，严重度降为低 | 中 |
| 6.2 | 是否有超过**分级阈值**未复习的「✅ 已掌握」知识点 | 阈值按证据强度：`low` 30 天、`medium` 60 天、`high` 不降级（见 [compile_subject_workflow.md](compile_subject_workflow.md) 第五节第 3 点）。**📘 已学未测不在本项范围内** | 中 |
| 6.8 | `topic_kind: memory_item` 的档案是否有 `next_review`；其余两档的 `next_review` 是否已留空 | 前者缺失说明间隔重复没跑起来，后者有值说明把固定日程误用到了解题型知识点上 | 中 |
| 6.9 | 是否有 `next_review` 已过期超过 14 天的 `memory_item` | 复习清单一直没被执行，提示用户该背了 | 低 |
| 6.10 | 档案的 `topic_kind` 是否为三档枚举之一，且正文第二段的形态与之匹配 | 第二段用错模板（如给篇目档案写「个人错因史」），或出现第四种取值 | 中 |
| 6.3 | 是否有错误次数 ≥3 但「下一步」无错因假设的档案 | 未触发错因假设验证 | 低 |
| 6.4 | 是否有档案 `prerequisites` 为空 | 提示可补全前置关系 | 低 |
| 6.5 | 档案 slug 是否违反命名约束 | 含数字后缀、日期、题号、`topic-*`/`item-*`/`untitled` 占位名、超 3 段纯拼音（禁止形态见 [topic_templates.md](../templates/topic_templates.md) 第一节第 2 小节）。这类名字说明建档时粒度三问没过 | 中 |
| 6.11 | 档案的 `topic` 中文名在 [topic_vocabulary.md](../templates/topic_vocabulary.md) 中存在同义条目、但 slug 与词表不一致 | 同一知识点被起了两个名字，错因史会被劈成两半——这是词表要防的首要问题 | 中 |
| 6.6 | **孤儿档案**：无任何作答证据（`error_count = 0` 且无练习记录）且「考点要义」不足 100 字 | 粒度过小或提取过碎的产物，建议合并到上位知识点或删除。注意与正常的 📘 已学未测区分——后者「考点要义」是充实的，只是还没测 | 中 |
| 6.7 | 档案 `status` 为 📘 已学未测，但 `error_count > 0` 或存在作答记录 | 状态未随首次作答流转 | 中 |

|------|------|----------|

## 二、中严重度问题

...

## 三、低严重度提示

...

## 四、汇总

| 严重度 | 数量 |
|--------|------|
| 高 | 4 |
| 中 | 7 |
| 低 | 12 |

### 无问题时

不要输出空表格，直接一句话回复即可：

> 体检通过：128 条记录、43 个知识点档案，未发现一致性问题。

## 二之二、档案清理（批量修复）

体检"只报告不改写"的前提是**问题是零星的**，逐项确认可行。当编译层因抽取规则失效而长出成百上千个空壳档案时，逐项确认不现实——需要一个**按模式批量**处理的动作。

> [!WARNING]
> 本操作**只删改编译层**（`subjects/<学科>/topics/`、`colleges/` 下的档案与索引），**永不触碰 `raw/`**。编译层可从源层重建，所以批量删除是安全的；这也是为什么批量修复只在这一层被允许。

### 何时用

- 体检的 6.5（slug 违反命名约束）、6.6（孤儿档案）、6.11（同义分叉）命中数量 **> 20**
- 用户直接描述症状："档案名全是乱码"、"一个知识点有好几份档案"

### 执行步骤

1. **按模式分组，不逐个列举**。把不合格档案归成可命名的类，每类给出数量与 2-3 个样例：

   | 模式 | 正则示例 | 处置 |
   |---|---|---|
   | 随机哈希 | `^topic-[0-9a-f]{8}$` | 删除（无语义，无法合并） |
   | 章节号 / 流水号 | `^(exercises-)?ch\d+$`、`^compilation-\d+$` | 删除 |
   | 按年份 / 份数切分 | `.*\d{4}年$`、`.*检测\d+$` | 删除；其内容由重编按正确知识点重新归集 |
   | 同义分叉 | `prose` / `prose-reading` / `prose-阅读` | **合并**到词表规范名，保留错因史 |
   | 孤儿档案 | `error_count = 0` 且「考点要义」< 100 字 | 删除 |

2. **先出清单再动手**。输出上表的实际统计（每类数量 + 样例 + 处置），请用户**按类**确认——可以只批准其中几类。

3. **合并的处置规则**（与删除不同，要保内容）：
   - 目标档案取 [topic_vocabulary.md](../templates/topic_vocabulary.md) 的规范名；
   - 被合并档案的「个人错因史」按日期**归并排序**后并入，重算「是否重复」列；
   - `sources` 取并集去重；`error_count` 重算而非相加（同一次错误可能被记了两遍）；
   - 合并完成后删除源档案，并在学科 `_index.md` 的两张索引表里删掉对应行。

4. **删除后必须重编**。删除只是清场，`raw/` 里的记录还在——必须紧接着对受影响学科跑一次**重新编译**（第三节），让正确的知识点档案重新长出来。**只删不编会让源记录变成孤儿**（体检 1.2 会报）。

5. **记入 log**，格式见第六节。

### 与全量重编的关系

档案清理**不能替代**重编，反过来也不行：

- 若**抽取规则已修正**，直接跑全量重编即可——旧档案会被删除并按新规则重建，不需要单独清理。
- 若**抽取规则未修正**，清理完再重编会长出同样的垃圾。**先确认规则已更新，再动手。**

> 换句话说：档案清理适用的场景是"规则已改好，但存量档案里混有按旧规则生成的、且重编不会自动覆盖的残留"（如 slug 变更后旧文件名不会被新编译覆盖）。**规则没改就清理，等于白做。**

## 三、重新编译

只重建**一个学科**（`subjects/<学科>/`）或**一个升学目标**（`colleges/groups/` 或 `colleges/majors/` 下的单个档案）的编译产物，源层与其余学科/目标不受影响。

> **重编的编排在本文件**（范围确定、用户确认、log）；**具体怎么重放由各族自己定义**——学科族见 [compile_subject_workflow.md](compile_subject_workflow.md) 的「本族的重放规则」，升学族见 [compile_admission_workflow.md](compile_admission_workflow.md) 的同名章节。两族的重放规则截然不同：学科族**必须按 `date` 升序**（错因史的「是否重复」列与状态流转依赖顺序），升学族**顺序无关**（pull 模型每次从全量资料重新取数）。

### 何时用重新编译而非全量重编

| 场景 | 选择 |
|------|------|
| 体检发现的编译层/源层不一致问题集中在同一学科 | 重新编译该学科 |
| 某个专业组/专业的档案数据明显错误或过期 | 重新编译该目标 |
| 手工改动过某一学科目录下的文件，导致该科状态混乱 | 重新编译该学科 |
| 问题跨越多个学科或多个升学目标 | 走[全量重编](#四全量重编) |
| 编译规则本身发生变更（如新增字段） | 走[全量重编](#四全量重编) |

### 确定范围

与用户确认范围，二选一，范围不明确时向用户追问，不擅自扩大或缩小：

1. **学科范围**：九科枚举中的一个学科（如"数学"）。
2. **升学目标范围**：`profile.md` 目标列表中的一个院校专业组或一个专业（如"北京大学 01 专业组""计算机科学与技术"）。

### 执行前必须确认

向用户说明三点后再执行：

1. **会删除什么**：仅该学科的 `subjects/<学科>/topics/` 下全部档案及该学科 `_index.md` 的动态章节；或仅该升学目标对应的单个 `colleges/groups/<...>.md` / `colleges/majors/<...>.md` 档案；
2. **不会动什么**：`raw/`、`profile.md`、`output/`，其余学科与其余升学目标的档案，以及该学科 `_index.md` 的静态章节（高频主题、高频考点、学习目标）；
3. **可恢复性**：与全量重编相同——该范围内的编译层可从源层重建，重编安全；但若源层本身缺字段（如缺 `topics`），重编后这部分内容会**丢失**——建议先跑数据体检，修完该范围内的高严重度问题再重编。

### 常见触发原因

- 数据体检发现的 1.x 类（编译层与源层不一致）问题集中在同一学科或同一升学目标；
- 手工编辑过某一学科目录或某个升学档案下的文件，导致该范围状态混乱；
- 单个专业组/专业的录取或就业数据更新后需要刷新对应档案。

## 四、全量重编

删除并从源层完整重建**整个**编译层（`subjects/` 与 `colleges/` 下的全部档案）。**范围只涉及一个学科或一个升学目标时，改用[重新编译](#三重新编译)**——删除面小、重放成本低，是更常见的选择。

### 执行顺序（两族各跑一遍）

1. **学科族**：按 [compile_subject_workflow.md](compile_subject_workflow.md) 的「本族的重放规则」，对全部启用学科按 `date` **升序**重放 `raw/notes/` 中的学科记录。
2. **升学族**：按 [compile_admission_workflow.md](compile_admission_workflow.md) 的「本族的重放规则」，读 `profile.md` 的目标列表重新拉取；顺序无关，可与上一步并行。
3. **一分一段表索引**：由升学族的重放步骤 3 重建（按省份，不受目标列表限制）。
4. **Root `_index.md`**：两族都跑完后统一重算学科状态概览与目标进度——它汇总两族结果，必须最后刷新。

### 执行前必须确认

向用户说明三点后再执行：

1. **会删除什么**：`subjects/<学科>/topics/` 与 `colleges/groups/`、`colleges/majors/` 下的全部档案，以及各 `_index.md` 的动态章节（知识点索引、薄弱点索引、正确率趋势、目标索引）；`colleges/scores-distribution.md` 会被重新扫描重建（不会先删除再可能为空，而是直接覆盖为最新扫描结果）；
2. **不会动什么**：`raw/`、`profile.md`、`output/`，以及学科 `_index.md` 的静态章节（高频主题、高频考点、学习目标）；
3. **可恢复性**：编译层可从源层完整重建，因此重编是安全的；但若源层本身缺字段（如缺 `topics`），重编后这部分内容会**丢失**——所以**建议先跑数据体检**，修完高严重度问题再重编。

### 常见触发原因

- 数据体检发现的 1.x 类（编译层与源层不一致）问题**跨越多个学科或多个升学目标**；
- 编译规则变更（如本次架构升级后首次运行），所有已编译档案都可能过时；
- 用户明确要求"全部重新编译"。

## 五、学年归档

### 目的

高三学生的日常检索不需要高一的错题参与，但这些数据不能删除。归档把旧学年的源层移出活跃检索范围，同时**保留知识点档案的全量历史**。

### 归档单位

按**学年**归档，不按知识点或学科：

```
archive/
└── 2025-2026-高一/
    └── raw/
        ├── sources/YYYY/MM/
        └── notes/YYYY/MM/
```

> [!IMPORTANT]
> **升学资料不参与学年归档**。`raw/notes/` 中 `doc_type: admission_data` 的记录（投档线、一分一段表、招生简章、就业年报）**留在活跃层不动**，其对应的 `raw/sources/` 原件同理。
>
> **为什么必须排除**：升学族是目标驱动（pull）编译——档案里的数据不是"存下来的"，是每次重编时从 `raw/notes/` **重新查出来的**。而归档后的数据默认不参与检索（见下方「归档后的行为」），所以一旦把升学资料移进 `archive/`，下次全量重编就会让 `colleges/groups/` 丢掉已归档年份的投档线与最低位次、`colleges/scores-distribution.md` 丢掉对应年份的行，体检 5.12 还会把这个当成"索引与记录不一致"误报。
>
> 学科族没有这个问题，因为第 3 步「保留档案」明确不动知识点档案；升学族没有对应兜底。
>
> 从语义上讲这也更正确：升学资料不属于任何"学年"，只属于某个**招生年度**，且它的价值不随学年衰减——一分一段表的用途正是跨年对比，高三做差距分析时要用的恰恰是高一高二导入的那几年数据。

### 执行步骤

1. **确定范围**：与用户确认学年起止日期（如 2025-09-01 至 2026-08-31）与标签（如 `2025-2026-高一`）。
2. **移动源层**：把该区间内的 `raw/sources/YYYY/MM/` 与 `raw/notes/YYYY/MM/` 子树移入 `archive/<学年>/raw/` 下的同名路径。**移动而非复制**，避免活跃层与归档层出现双份。
   - **例外：跳过升学资料**——`raw/notes/` 中 `doc_type: admission_data` 的记录（文件名含 `-admission-`）留在原处不动，其 `source_path` 指向的 `raw/sources/` 原件也一并保留。理由见上方「归档单位」。
   - 该区间内**只有**升学资料时，告知用户本学年无可归档的学科记录，不建空的 `archive/<学年>/` 目录。
3. **保留档案**：`subjects/` 下的知识点档案**不动**。知识点不随学年失效——"函数单调性"在高三依然要用，它的高一错因史仍有诊断价值。
4. **标记档案来源**：档案 `sources` 中指向已归档记录的路径，改写为 `archive/<学年>/raw/notes/...`，并在该行标注「（已归档）」，保证引用不断链。
5. **写归档摘要**：在 `archive/<学年>/summary.md` 记录该学年的关键数据（各科正确率、考试成绩、期末薄弱点快照），供日后回顾时无需展开全部记录。
6. **精简索引**：Root `_index.md` 的「历次考试成绩记录」中，已归档学年的成绩折叠为一行摘要；学科 `_index.md` 的薄弱点索引不变（因为档案未动）；`colleges/_index.md` 与 `colleges/scores-distribution.md` **完全不受归档影响**（升学资料未被移动）。
7. **记入 log**。

### 归档后的行为

> 以下规则只作用于**学科族**记录——升学资料从不进入 `archive/`，因此始终参与检索与编译。

- **默认跳过**：`ask`、`learn`、`eval`、`report`、全量重编等流程默认不检索 `archive/`；
- **显式包含**：用户明确要求（如"把高一的数据也算上"）时才检索，且在输出中标注来源为归档数据；
- **不可静默引用**：归档数据不得作为当前学情的证据出现在薄弱点排序或掌握判定中。

### 恢复

用户要求取回某个学年时，把 `archive/<学年>/raw/` 移回 `raw/` 对应路径，还原档案 `sources` 中的路径标注，然后走一次全量重编。
