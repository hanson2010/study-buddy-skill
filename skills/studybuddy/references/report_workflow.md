# 学情追踪工作流（report_workflow）

本文件定义学情追踪的处理流程，自动统计并可视化学习数据，生成学情报告保存到 `output/` 目录，为学生和家长提供全面的学习分析。

---

## 一、学情追踪目标

- **数据可视化**：将分散的学习数据汇总成直观的报告
- **趋势分析**：识别学习趋势，发现进步或退步的学科和知识点
- **薄弱点预警**：预测可能的薄弱点，提前干预
- **个性化建议**：基于数据给出针对性的复习建议
- **家长沟通**：生成适合家长阅读的学习报告

---

## 二、数据来源

### 1. profile.md
- 学生基础信息（姓名、年级、文理科、教材版本）

### 2. _index.md 文件
- **Root _index.md**：全局复习优先级、历次考试成绩、各科状态汇总
- **学科 _index.md**：各学科知识点索引（全量状态计数）、薄弱点索引、正确率趋势

### 3. subjects/<学科>/topics/ 知识点档案（**主要来源**）

> [!IMPORTANT]
> **统计优先汇总知识点档案，而不是遍历 `raw/notes/` 全量文件**。档案已经把每个知识点的错因史、证据强度、状态收敛好了，直接汇总即可；遍历日期文件既慢又容易漏。只有在需要引用某道具体题目时才下沉。

从档案可直接读取：
- 各知识点的错误次数、错因类型分布、状态、证据强度
- 各知识点的最近错误日期与最近复习日期
- 各知识点的已用资源（视频、练习及正确率）
- 待验证的错因假设与下次复习安排

### 4. output/ 目录
- 日志文件（`output/YYYY/MM/YYYY-MM-DD-log.md`）：记录每次学习、复习、改错等活动的操作概要，是报告统计学习天数、学习时长、活动类型等数据的**主要来源**
- 提问记录（`ask` 追加）：学生反复追问的知识点本身就是薄弱信号，值得在报告中体现
- 学情报告文件

### 5. raw/ 目录（按需下沉）
- `raw/notes/`：需要引用具体题目、完整解析或核对档案数据时
- `raw/sources/`：需要回溯原始图片或文档时
- 默认跳过 `archive/` 下的已归档学年

## 三、报告类型

> [!IMPORTANT]
> **正文的章节结构以 [templates/report_file_templates.md](../templates/report_file_templates.md) 为唯一定义**，本节只说明各报告的适用场景与定位，不重复列举章节，以免两处产生分歧。

### 1. 日报（daily）

**适用场景**：每天的学习任务提醒（主要由外部自动化任务定时调用），用于当天快速浏览学习重点

**定位**：最简化，聚焦「今日做什么」，语气轻松，降低挫败感。正文结构见模板文件的「日报正文示例」。

### 2. 周报（weekly）

**适用场景**：按周生成（由用户手动请求，或由外部自动化任务定时调用），总结一周的学习情况

**定位**：简化版，聚焦「本周回顾 + 下周展望」，保持简短便于快速浏览。正文结构见模板文件的「周报正文示例」。

### 3. 月报（monthly）

**适用场景**：按月生成（由用户手动请求，或由外部自动化任务定时调用），总结一个月的学习情况

**定位**：完整版，用于月度复盘，含目标进度对比（数据来自 `profile.md`）；不含「下月复习计划」。正文结构见模板文件的「月报正文示例」。

### 4. 专项报告（special）

**适用场景**：针对特定需求生成的专项分析报告

**包含类型**：
- **薄弱点专项报告**（`weak_points`）：分析所有薄弱点的详细情况
- **考试对比报告**（`exam_compare`）：对比多次考试的成绩变化
- **学科分析报告**（`subject_analysis`）：深入分析某一学科的学习情况
- **目标差距分析报告**（`gap_analysis`）：目标位次与当前位次的差距，由 `aim` 生成
- **学习规划报告**（`study_plan`）：目标分翻译成知识点补漏优先级，由 `aim` 生成

> **专项报告的文件名**：`YYYY-MM-DD-report-special-<subtype>.md`（如 `2026-07-12-report-special-gap-analysis.md`），以便同一天生成多份不同专项报告时不互相覆盖。
>
> `gap_analysis` 与 `study_plan` 由 [aim_workflow.md](aim_workflow.md) 产出，但**文件归 `output/`**——与其他学情报告一致：档案是当前状态，`output/` 是时点快照。`colleges/` 只放编译出来的档案与索引，不放生成的报告。

## 四、学情追踪流程

### 0. 数据充足性检查（仅定时自动化调用时）

**适用场景**：日报、周报、月报由外部自动化任务定时调用时

**检查规则**：
- **日报数据不足条件**：当天不存在急需跟进的学习任务（即所有薄弱点均为「已掌握」状态且无待处理练习题/复习任务）。**📘 已学未测的知识点不算"急需跟进"**——否则每导入一份资料就会让日报连续多日被判为有任务，把提醒变成噪音；它只在周报/月报里作为一行汇总出现
- **周报数据不足条件**：统计周期内（7天）批改题目数 < 5 道 或 学习天数 < 2 天
- **月报数据不足条件**：统计周期内（30天）批改题目数 < 10 道 或 学习天数 < 5 天

**处理方式**：
- 当数据不足时，**跳过本次报告生成**，不输出报告文件
- 记录跳过原因到日志文件中
- 下次触发时重新检查

**手动触发**：用户手动请求生成报告时，不受数据充足性限制，正常生成报告

### 1. 数据收集与整理

**统计范围**：默认只统计**主修学科**（语数外 + 选考三科；选科未定时为全部九科）。学考科目不进各科表现表与复习优先级，仅在其有活动时于报告末尾附一行说明。

**数据收集**（按此顺序，避免不必要的全量遍历）：
- 读取 root `_index.md` 获取全局数据与启用学科范围
- 读取各主修学科 `_index.md` 获取知识点索引（全量状态计数，含 📘 已学未测）、薄弱点索引与正确率趋势
- 读取 `subjects/<学科>/topics/` 下的知识点档案，汇总错因类型分布、证据强度分布、状态变化
- 遍历统计周期内所有 `output/YYYY/MM/YYYY-MM-DD-log.md` 日志文件，汇总学习、复习、改错等活动记录（学习天数、学习时长、活动类型等）
- **仅在需要引用具体题目时**，才顺着档案的 `sources` 数组打开对应的 `raw/notes/` 记录

**数据整理**：
- 按时间维度汇总（日、周、月）
- 按学科维度汇总
- 按知识点维度汇总
- 按错误类型维度汇总

### 2. 数据统计与分析

**正确率统计**：
- 各学科正确率计算
- 各知识点正确率计算
- 正确率趋势分析（环比、同比）

**错误类型统计**：
- 概念不清、计算失误、审题错误、方法不当等类型的分布
- 各错误类型的变化趋势

**薄弱点分析**：
- 薄弱点数量统计
- 薄弱点变化分析（新增、改进、已掌握）
- 薄弱点优先级排序

**学习时长统计**：
- 每日学习时长
- 每周学习天数和总时长
- 各学科学习时长分配

### 3. 趋势分析

**正确率趋势**：
- 近7天/30天正确率变化
- 各科正确率对比趋势

**薄弱点趋势**：
- 薄弱点数量变化趋势
- 各知识点薄弱点状态变化

**排名趋势**：
- 总分排名变化趋势
- 各科排名变化趋势

### 4. 个性化建议生成

**基于薄弱点**：
- 针对薄弱知识点推荐复习内容
- 推荐相关视频资源
- 生成针对性练习题

**基于趋势**：
- 针对下降趋势的学科建议加强练习
- 针对上升趋势的学科建议保持并拓展

**基于学习时长**：
- 建议合理分配各学科学习时间
- 建议增加薄弱学科的学习时间

### 5. 报告生成与输出

**报告格式**：Markdown 文件

**存储位置**：`output/YYYY/MM/`

**文件名格式**：`YYYY-MM-DD-report-<report_type>.md`（如 `2026-07-12-report-weekly.md`）

**输出内容**：
- 报告标题和生成时间
- 核心数据概览（表格形式）
- 详细分析（文字描述）
- 可视化图表（ASCII 图表或 Markdown 表格）
- 个性化建议（含下周展望，仅周报）

### 6. 报告推送（Webhook，可选）

生成报告并写入文件后，按以下规则决定是否推送到外部系统：

- **检测环境变量 `STUDYBUDDY_REPORT_WEBHOOK`**：
  - **变量存在且非空**：将报告**正文**（不含 Frontmatter）以 HTTP `POST` 方式发送到该地址。
  - **变量不存在或为空**：**安静跳过**——不推送、不向用户输出任何与此相关的提示。
- **失败处理**：推送失败仅记录日志，不影响报告已生成与落盘，也不阻塞主流程。

#### 推送契约

```
POST {STUDYBUDDY_REPORT_WEBHOOK}
Content-Type: application/json

{"content": "<报告正文 Markdown>"}
```

两条必须满足的要求：

1. **剥离 Frontmatter**：只发送正文，即跳过文件开头两个 `---` 分隔符之间的元数据块。
2. **用真正的 JSON 序列化器编码正文**。报告正文必然是多行文本，且常含 `"`、`\`、换行；这些字符在 JSON 字符串中必须转义。**严禁用字符串拼接或 shell 变量插值拼出请求体**——换行符在 JSON 字符串里非法，直接拼接会让每一次推送都发出格式错误的请求体。

#### 各环境的实现方式

Agent 应根据当前环境可用的能力任选其一，不绑定特定 shell 或工具名：

**PowerShell**（`ConvertTo-Json` 负责转义）：
```powershell
$body = @{ content = (Get-Content '<报告文件路径>' -Raw -Encoding UTF8) -replace '(?s)\A---\r?\n.*?\r?\n---\r?\n' } | ConvertTo-Json -Compress
Invoke-RestMethod -Uri $env:STUDYBUDDY_REPORT_WEBHOOK -Method Post -ContentType 'application/json' -Body $body
```

> [!WARNING]
> `-Encoding UTF8` **不可省略**。Windows PowerShell 5.1 的 `Get-Content` 默认按系统 ANSI 代码页读取，报告正文中的中文会变成乱码后再被推送出去（且因为 JSON 本身合法，接收端不会报错，只会静默收到乱码）。

**Python**（`json.dumps` 负责转义）：
```python
import json, os, re, urllib.request
text = re.sub(r'\A---\n.*?\n---\n', '', open('<报告文件路径>', encoding='utf-8').read(), flags=re.S)
data = json.dumps({'content': text}).encode('utf-8')
req = urllib.request.Request(os.environ['STUDYBUDDY_REPORT_WEBHOOK'], data=data,
                             headers={'Content-Type': 'application/json'})
urllib.request.urlopen(req)
```

**curl + jq**（`jq -Rs` 负责转义）：
```bash
sed -e '1{/^---$/{:a;N;/\n---$/!ba;d}}' '<报告文件路径>' \
  | jq -Rs '{content: .}' \
  | curl -sS -X POST -H "Content-Type: application/json" --data-binary @- "$STUDYBUDDY_REPORT_WEBHOOK"
```

### 操作概要记入 log 文件

每次执行学情追踪流程后，必须将操作概要记入 `output/YYYY/MM/YYYY-MM-DD-log.md` 文件：

**记录内容**：
- **操作类型**：日报/周报/月报/专项报告
- **报告类型**：daily/weekly/monthly/special
- **生成的文件**：创建的报告文件路径
- **统计周期**：分析的起止日期
- **核心数据**：学习天数、学习时长、批改题目数量、正确率、薄弱点数量

**记录格式**：
```markdown
## 操作记录

### YYYY-MM-DD HH:MM:SS
- **操作类型**：学情周报
- **报告类型**：weekly
- **生成文件**：output/2026/07/2026-07-12-report-weekly.md
- **统计周期**：2026-07-06 至 2026-07-12
- **核心数据**：学习5天，时长12小时，批改45题，正确率78%，薄弱点8个
```

## 七、与 _index.md 的集成规则

### 数据同步
- **报告生成后**：不直接修改 `_index.md`，报告作为独立输出文件保存
- **薄弱点更新**：薄弱点的状态变化仍通过 `_index.md` 记录，报告仅读取数据

### 报告引用
- 在 root `_index.md` 的「最近报告」部分记录生成的报告路径
- 方便快速查阅历史报告

## 八、报告生成时机

| 报告类型 | 生成时机 | 触发方式 | 数据充足性检查 |
|----------|----------|----------|----------------|
| 日报 | 每天 20:00 | 由外部自动化任务定时调用 | ✅ 无待跟进任务时跳过 |
| 周报 | 每周日 20:00 | 由外部自动化任务定时调用（或用户手动请求） | ✅ 数据不足时跳过 |
| 月报 | 每月最后一天 20:00 | 由外部自动化任务定时调用（或用户手动请求） | ✅ 数据不足时跳过 |
| 专项报告 | 用户请求时 | 手动触发 | - |
